# 项目提示词迭代记录

本文件记录「商业化改造」过程中每一轮的优化提示词（自设规格 → 执行 → 验收）。
每一轮完成后核对验收标准，全部达标才进入下一轮。

---

## 第 1 轮提示词（工程质量基线）→ v1.1.0

**目标**：把课程作业级别的代码提升到「可维护、可验证、可交付」的工程基线。

**任务清单**：

1. **配置校验**：新增 `config.validate_config()`，启动时检查阈值/冷却/置信度/摄像头编号的合法性，不合法的打印明确警告（不崩溃）。
2. **容错增强**：
   - `AttendanceRecorder.load_checked_names()` 遇到损坏/乱码的 CSV 时记录警告并按空记录处理，不得崩溃；
   - `register_face()` 限制姓名长度（≤50 字符），给出友好错误。
3. **日志轮转**：`main.py` 日志文件改用 RotatingFileHandler（1MB × 3 份），避免长期运行撑爆磁盘。
4. **测试补强**：新增 `tests/test_register.py`（假检测器/假特征器覆盖注册全流程与错误分支）与 `tests/test_config.py`；损坏 CSV 容错测试。
5. **覆盖率**：接入 pytest-cov，核心逻辑（utils/storage、imutils、register、checkin 引擎）覆盖率 ≥ 80%，CI 强制 `--cov-fail-under=80`。
6. **CI**：新增 GitHub Actions（`.github/workflows/ci.yml`），push/PR 自动安装 CPU 版依赖并跑全部测试 + 覆盖率门禁。
7. **版本**：pyproject.toml 版本号升至 1.1.0。

**验收标准**：
- [ ] 本地 `pytest --cov` 全绿且核心覆盖率 ≥ 80%
- [ ] GitHub Actions CI 通过（含覆盖率门禁）
- [ ] 损坏 CSV / 非法配置 / 超长姓名 均有友好处理且有测试覆盖

## 第 2 轮提示词（功能完备性）→ v1.2.0

**目标**：补齐一个真实产品应有的管理能力，让用户无需手改数据目录即可完成日常操作。

**任务清单**：

1. **学生管理**：
   - `FeatureDatabase.delete(name)`：删除特征向量与人脸照片，返回是否成功；
   - `FeatureDatabase.details()`：返回姓名 + 注册时间（文件 mtime）；
   - `register.py` 新增 `--list`（列出学生与注册时间）与 `--delete 姓名`（删除学生）。
2. **控制台菜单升级**：`main.py` 菜单改为 5 项——1 注册 / 2 签到 / 3 查看信息（含注册时间、今日出勤明细）/ 4 删除学生 / 5 退出。
3. **参数校验**：`checkin.py --tolerance` 校验取值范围 (0, 2]，越界给出提示。
4. **测试补强**：删除/详情/损坏 CSV/配置校验/注册流程 全部有单测。
5. **文档同步**：README 菜单与命令行参数表更新。

**验收标准**：
- [ ] 全部单测通过，CI 通过
- [ ] 新增功能均可通过命令行完成，无需手改文件
- [ ] README 与实际行为一致

## 第 3 轮提示词（发布准备）→ Release

**目标**：按商业化发布标准交付。

**任务清单**：

1. **CHANGELOG.md**：按版本记录 v1.0.0 / v1.1.0 / v1.2.0 变更。
2. **README 徽章**：CI 状态徽章 + MIT 徽章；宣传页与 Release 链接齐全。
3. **商业化检查清单核对**（全部通过才可发布）：
   - 错误处理：所有入口与 IO 边界有友好错误，无裸 traceback；
   - 测试：核心逻辑覆盖率 ≥ 80%，CI 门禁在线；
   - 文档：README / 宣传页 / CHANGELOG 与实际行为一致；
   - 安全：无硬编码密钥；CSV 注入已防；用户输入已校验；
   - 可复现：requirements 锁定版本范围，安装说明含国内镜像路径。
4. **GitHub Release**：打 tag `v1.2.0`，Release Notes 含功能摘要、安装方式、演示方式与宣传页链接。

**验收标准**：
- [ ] 检查清单全部通过
- [ ] Release 页面正常展示，附自动生成的源码包
